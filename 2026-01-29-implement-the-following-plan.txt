  4. Auth Middleware:
  // middleware/auth.js
  import jwt from 'jsonwebtoken';

  export function requireAuth(req, res, next) {
    const token = req.headers.authorization?.replace('Bearer ', '');

    if (!token) {
      return res.status(401).json({ error: 'No token provided' });
    }

    try {
      const decoded = jwt.verify(token, process.env.JWT_SECRET);
      req.user = decoded;
      next();
    } catch (error) {
      return res.status(401).json({ error: 'Invalid token' });
    }
  }

  // Usage
  app.post('/api/ai/generate', requireAuth, async (req, res) => {
    // req.user has userId, can track usage
  });

  4. Why Revoke API Keys (The Important One)

  Your thinking: "I'll just delete them from the code, problem solved!"

  Why that doesn't work:

  Git History Never Forgets

  When you commit a file to git, it's permanently in the history. Deleting it
  later doesn't remove it from old commits.

  # Your git history looks like this:
  commit d12d3ab - "add config.js with API keys"  ← KEYS VISIBLE HERE
  commit 77a0f7f - "update keys"                   ← KEYS VISIBLE HERE
  commit e3e154d - "remove keys from config.js"    ← Keys gone NOW, but...

  # Anyone can do this:
  git checkout d12d3ab
  cat public/config.js
  # Boom, they have your keys

  Even worse - GitHub stores all history publicly:

  # Anyone can view old commits on GitHub:
  https://github.com/yourname/lovable-prototype/blob/d12d3ab/public/config.js

  # Or clone the repo and search history:
  git clone https://github.com/yourname/lovable-prototype
  git log --all --full-history -- "*config.js"
  git show d12d3ab:public/config.js
  # Your keys are RIGHT THERE

  Real Attack Scenario

  1. Attacker finds your repo (even if you make it private now, someone might
  have cloned it)
  2. Searches git history: git log --all --grep="API"
  3. Finds commit with keys: git show d12d3ab:public/config.js
  4. Copies your OpenAI key
  5. Spins up 100 servers making requests to OpenAI with YOUR key
  6. You get a $10,000 bill from OpenAI next month

  This isn't theoretical - this happens constantly. OpenAI/Anthropic have bots
  scanning GitHub for exposed keys.

  How to Fix It Properly

  Step 1: Revoke the keys (make them useless)
  - OpenAI: https://platform.openai.com/api-keys → Delete key
  - Anthropic: https://console.anthropic.com/settings/keys → Revoke
  - Google: https://console.cloud.google.com/apis/credentials → Delete
  - Jina: https://jina.ai/settings → Revoke

  Step 2: Remove from git history
  # Option A: BFG Repo-Cleaner (fast, easy)
  brew install bfg
  bfg --delete-files config.js
  bfg --delete-files .env
  git reflog expire --expire=now --all
  git gc --prune=now --aggressive
  git push --force

  # Option B: git filter-branch (slower, built-in)
  git filter-branch --force --index-filter \
    "git rm --cached --ignore-unmatch public/config.js .env" \
    --prune-empty --tag-name-filter cat -- --all
  git push --force

  Step 3: Generate new keys (after old ones are revoked and removed from
  history)

  Step 4: Never commit them again
  # Add to .gitignore
  echo "public/config.js" >> .gitignore
  echo ".env" >> .gitignore
  echo ".env.local" >> .gitignore

  # Use environment variables or backend

  Why This Matters for Your Project

  Even though this is a school project, if someone steals your keys:
  - You personally get charged for their API usage
  - OpenAI charges ~$0.03 per 1K tokens for GPT-4
  - Someone could rack up $1000+ in a day
  - Your credit card gets hit, not your school

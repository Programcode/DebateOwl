## Architecture to implement

Keep React 18, Node 22, npm and the committed lockfile. Use the installed Tiptap 3.31.3, Hocuspocus 4.7.0 and Yjs 13.6.32. Supabase remains the authority for identity, current membership, metadata and durable state. One Node collaboration process owns live documents; enforce one writer per document with a dedicated PostgreSQL session advisory lock, and close writers if the lock connection dies. No Redis, second account system, managed collaboration purchase or new editor evaluation.

The canonical document is the existing structured Yjs document. JSON/text is a projection at a known durable sequence, not another writable copy. Keep binary updates, snapshots and versions in private storage behind authorized operations. Serialize append, restore and proposal acceptance. Persist before Saved or broadcast. Recheck current membership for incoming operations and outgoing content, including awareness. Coordinate access changes with the gateway so successful removal acknowledgement comes only after queued delivery and subscriptions are fenced. A stale JWT or successful channel join is insufficient.

Use existing RPCs for metadata, with their expected workspace revision and request IDs. Add only data used by the current milestone. New workspace children need workspace-scoped foreign keys and membership RLS; private snippets and Google connections need account ownership. Never move personal rows into shared scope implicitly. Keep TanStack Query for server metadata and account-scoped IndexedDB for local document recovery. Add editor bindings or a persistence package only where the installed APIs leave a concrete gap.

Retain the existing app style and controls. Lazy-load workspace/editor/converters. Desktop gets files, document and a collapsible working panel; phones show one pane at a time. Each milestone includes English, Spanish and Hungarian copy, keyboard operation, visible focus, labelled controls, non-color-only diffs/cursors, 200% zoom, IME and touch editing. No redesign project.
